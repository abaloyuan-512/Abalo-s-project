## 给新人的快速认知
1. **这是一个空骨架仓库**：暂时没有 `src/`、`app/`、`tests/`、`package.json`、`pyproject.toml` 等常见工程文件。
2. **你现在的核心任务是补齐工程基础设施**：先确定技术栈，再建立目录、依赖管理、运行与测试流程。
3. **文档先行很关键**：每增加一个模块，都同步补充 README，降低后续协作成本。

## 建议优先补齐的内容（按顺序）
### 1) 技术决策与边界
- 明确项目语言与框架（如 Node.js / Python / Go / Java）。
- 定义项目目标、核心用户、MVP 功能边界。

### 2) 工程目录与约定
- 建议建立：
  - `src/`（核心代码）
  - `tests/`（测试）
  - `docs/`（设计与使用文档）
  - `scripts/`（自动化脚本）
- 同步补充代码规范与提交规范。

### 3) 运行与测试闭环
- 增加一条可执行的启动命令。
- 增加至少一条自动化测试命令。
- 引入基础 CI（如 GitHub Actions）保证每次提交可验证。

### 4) 协作规范
- 增加 `CONTRIBUTING.md`：分支策略、提交流程、代码评审要求。
- 增加 `CHANGELOG.md`：版本与变更记录。

## 新人学习路径建议
1. **第 1 天**：读 README、跑通最小示例、理解当前目标。
2. **第 2-3 天**：阅读目录约定与测试策略，提交一个小改动并走完整 PR 流程。
3. **第 1 周**：认领一个端到端小任务（需求 -> 开发 -> 测试 -> 文档）。
4. **第 2 周**：参与一次代码评审并反向优化文档，把隐性知识显性化。

## 给维护者的下一步建议
- 尽快补充“项目愿景 + 技术栈 + 启动命令 + 测试命令”四项最小信息。
- 约定统一分层（例如 `api/service/repository` 或 `controller/domain/infra`），避免后期重构成本。
- 在仓库早期就建立自动化检查，防止质量债务累积。
