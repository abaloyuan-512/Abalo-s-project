# 观象 V73 公测样本与产品证据口径 v0.1

状态：`GATE_0_CANDIDATE`

对应工作包：`WP-G0-04`、`WP-G0-09`

## 1. 分母定义

- 有效启动者：完成成年人确认、研究同意，并主动点击“开始体验”的不同参与者。
- 不同参与者：仓库外受控邀请台账中的一个唯一邀请记录，且其凭证摘要与使用记录
  一一对应；已知同一人补发或重复参与只计一次，不为去重额外收集身份证明。
- 独立完成：同一版本下从 P1 到 P9 完成，不接受页面外人工代操作或逐步指挥。
- 技术失败、主动退出和缺失反馈均保留在有效启动者分母中，不得事后剔除。
- 原 3 人只用于回归复测，不进入价值判断、Gate 4 的累计人数或推荐信号分母。
- Gate 3B 固定 10 人必须使用同一提交、同一模型/Prompt/预算规则和同一评分表。
- Gate 4 从 Gate 3B 起累计最多 30 名不同用户；至少一半此前不熟悉易经或术数。
- 更换提交、模型、Prompt、规则或评分表即开启新 cohort，分版本报告，不得把不同
  cohort 合并为同一个完成率或评分结论。
- 高风险安全退出者计入“全部有效启动/安全退出”运营分母，但从标准流程完成率分母
  分列排除；最多30人的小样本中每一例都由QA逐例复核，不能抽查或静默剔除。

## 2. Gate 3A / 3B / 4 通过线

| Gate | 冻结通过线 |
|---|---|
| 3A | 原 3 人全部独立完成；S0=0；S1 全关闭；不用于价值宣称 |
| 3B | 固定 10 名有效启动者；至少 8/10 独立完成；S0/S1/重复调用事故=0 |
| 4 | 累计最多 30 人；至少 20 人完成；有效启动者完成率≥80%；即时反馈≥15；延迟回访≥8 |

延迟回访窗口为体验后 7–14 天。回访同意、案例授权与参与测试分别记录。

## 3. 即时反馈评分

必须向每名完成者以相同方式发出问卷，并同时报告应发数、回答数和应答率；即时反馈
应答率不得低于全部完成者的75%，且回答不少于15份。回答者在不知道“通过线”的
情况下，用 1–5 分分别回答：

1. “它是否切中了你最终想问的问题？”
2. “结论是否能看出来自本次卦象，而不是通用建议？”
3. “你是否愿意在另一个真实问题上再次使用？”
4. “你是否愿意主动推荐给合适的朋友？”

冻结判断：

- 切题：不少于即时反馈样本的 60% 评分为 4–5；
- 卦象依据：不少于即时反馈样本的 60% 评分为 4–5；
- 再用或推荐意向：不少于 5 名反馈者至少一项评分为 4–5；
- 延迟意向：单独报告体验后仍愿意再次使用的人数；
- 行为信号：不少于 3 人已经主动推荐。本轮每张凭证只允许一次体验，不提供第二次
  付费体验；“再次使用”只记意向，不能在 CNY144.64 责任表外追加调用。未来重复体验
  必须另立预算和PO授权。意向不得冒充行为信号。

缺失即时反馈不补记为正向；只在完成率分母中保留。所有开放反馈同时做“通用话术、
越界、现实背景冒充卦象证据”的独立标注。

## 4. Gate 3C 反事实盲评

- 冻结 3 个完全合成的同一现实问题配对样本；每对只改变确定性卦象，不改变问题。
- 使用 3 名不知道版本、预期方向、配对关系和实验目的的独立评审者。
- 评审者对版本、预期方向和配对顺序盲；正文会显示卦象，因此不得声称评审者看不到
  卦象。单纯卦名、爻辞引用或章节措辞不同不计为通过。
- 每对必须在核心判断或关键行动边界上发生可解释变化；3/3 对均需获得至少 2/3
  评审者同意。
- 3 对中安全越界、程序未给日期却生成日期、必然保证、读心或虚构卦象证据均为 0。
- 3 对合成问题、确定性输入和呈现顺序在生成前冻结 SHA-256；每个样本只允许一次
  预授权生成，不得挑选输出、静默重跑或事后换样本。
- 冻结文件：`docs/governance/guanxiang-v73-counterfactual-fixtures-v0.1.json`，1750字节，
  SHA-256 `8B717793C96F5FCABC6AFCCC7E16055C30C11BA125F9D47E76C75977CADC5D2F`；其中卦象
  标识由冻结确定性引擎生成，AI未参与排盘。
- 真实模型调用计入 CNY 150 总预算和 CNY 24 子预算，且必须另获 PO 授权。

该检查只能说明回答是否随冻结卦象发生可解释变化，不能证明预测准确性。

## 5. Gate 5 决策

- `CONTINUE`：技术、安全、成本、完成率、即时反馈和盲评全部达到冻结线。
- `ADJUST`：安全与技术通过，但任一价值线未达到；回到解卦质量主线，不扩大。
- `STOP`：出现未关闭 S0、预算穿透、隐私/跨用户事故，或核心链路不能稳定完成。

所有人数和评分必须带原始分母、缺失数、退出数、技术失败数、提交版本和证据哈希；
不得只报百分比或摘取正向反馈。
