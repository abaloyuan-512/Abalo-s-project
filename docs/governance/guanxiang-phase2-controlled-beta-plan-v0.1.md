# 观象下一阶段推进计划 v0.1

状态：`SUPERSEDED_AFTER_INDEPENDENT_REVIEW`

替代文件：`docs/governance/guanxiang-v73-product-beta-control-v0.2.md`

说明：本草案经 PMO、反向论证官和独立质检官审查后，结论分别为
`CONDITIONAL PASS`、`REVISE`、`CONDITIONAL PASS / NO-GO`。本文件保留为
反证前历史版本，不得据此启动匿名开放或代码施工。

阶段名称：`Phase 2 — V73 受控公测与证据闭环`

## 1. 阶段判断

观象第一阶段可以按“产品基本功能与 P1–P9 完整体验基线已经完成”收束。V72 已由产品负责人验收、正式冻结并部署；确定性排盘、辨识定问、Direct Reading high 与 P1–P9 内容不需要在下一阶段重新设计。

但“公开可用”尚未完成。当前 `direct-reading/v2` 与其 intake 接口仍要求创建者身份，匿名用户会在 P6 后被拦截；手机端 P1–P9 也尚未完成逐页真实设备验收。因此，下一阶段不是继续增加功能，而是把冻结产品推进到：

> 匿名真实用户能在手机上完整体验，成本可控，问题可回收，产品价值可被验证。

本计划以 V72 为不可改写的基线。后续修改使用新分支、新规范、新提交、新标签和新站点版本，不覆盖 V72。

## 2. 阶段目标

本阶段只完成五个结果：

1. 匿名用户无需登录即可完整走完 P1–P9。
2. P1–P9 在常见手机浏览器与微信内置浏览器中达到基本可用。
3. 完成一轮 3 人复测、一轮 10 人测试和一轮最多 30 人的受控公测。
4. 获得可用于产品决策的结构化反馈，而不只收集“准不准”。
5. 在明确的模型调用预算、频率限制和停止开关下运行，不发生失控消耗。

## 3. 本阶段明确不做

- 不做原生 App、小程序或新的技术架构。
- 不做登录注册、会员、支付、积分、社区或运营后台。
- 不公开核心 GitHub 仓库、提示词、术数规则、评测集或用户案例原文。
- 不重做辨识、定问、确定性排盘、解卦内核、P1–P9 文案或美术方向。
- 不以“精准预测”“保证结果”等口径公开推广。
- 不开展不受控的大规模传播、投流或付费转化。
- 不生成程序未提供的具体日期，不把现实背景伪装成卦象证据。

## 4. 变更与缺陷分级

### P0：公测前必须解决

- 匿名用户无法完成 P1–P9。
- 重复点击、刷新或轮询导致重复生成和重复计费。
- 公开链路泄露密钥、身份、敏感请求或内部诊断信息。
- 成本限制、访问频率限制或停止开关失效。
- 高风险内容出现明显越界，或确定性排盘结果发生变化。

### P1：首轮 10 人测试前解决

- 手机端无法输入、按钮被遮挡、页面横向溢出、内容无法滚动。
- 关键文字难以阅读，P8 五幕或 P9 无法完整浏览。
- 错误提示使用户无法知道下一步该做什么。
- 微信内置浏览器中主链路中断。

### P2：记录但不阻塞首轮公测

- 轻微间距、动效节奏、装饰位置和低频视觉瑕疵。
- 不影响完成率或理解度的桌面端细节。
- 需要重新讨论产品方向的新功能建议。

## 5. 推进路径与验收门

### Gate 0：建立 V73 公测基线

任务：

- 保留 V72 冻结标签和源码，不在冻结版本上覆盖修改。
- 为公开访问、移动端修复和公测边界建立独立的版本化规范。
- 建立缺陷清单，每项记录页面、设备、复现步骤、严重级别和截图。
- 确认一次解卦成本上限、总预算上限和人工停止方式。

通过条件：变更范围、预算和停止条件得到产品负责人确认。

### Gate 1：解除匿名访问阻塞

任务：

- 将已有“登录用户直接使用、匿名用户受频率限制”的公开访问机制迁移到 Direct Reading V2 及 intake。
- 保留请求幂等、任务状态、公开字段白名单和不自动重复生成的现有保护。
- 不新增登录页，不要求访客登录 ChatGPT。
- 补齐匿名 POST、匿名轮询、重复请求、限流失败、上游失败与所有者访问回归测试。

通过条件：

- 电脑无痕窗口、手机浏览器和微信内置浏览器均可匿名走到 P9。
- 同一任务不会因为刷新、返回或重复点击而重复调用模型。
- 超过频率或预算时先阻断，且不会发起模型请求。
- 所有 Sites 测试、构建检查与 Python `pytest` 通过。

### Gate 2：手机端首轮修复

只允许调整响应式布局、字号、间距、溢出、视口高度和触控区域，不修改内容、算法、动线或模型契约。

按以下小批次实施和验收，每批完成后留一个检查点：

1. P1–P2；
2. P3–P4；
3. P5–P6；
4. P7；
5. P8 五幕；
6. P9；
7. P1–P9 全链路回归。

每页最少检查：横向溢出、文字行宽、键盘遮挡、底部操作区、安全区、滚动恢复、图片裁切和触控面积。

通过条件：主流窄屏和常规手机宽度下不存在 P0/P1 移动端问题，P8 五幕与 P9 均可完整阅读和操作。

### Gate 3：3 人复测与 10 人首轮测试

第一轮由原有 3 位同事复测，只验证：能否完成、哪里卡住、哪里读不懂、哪里过长、是否发生重复生成。

修完 P0/P1 后，邀请 10 名非项目成员测试。样本尽量包含：不了解易经的人、好奇者、怀疑者和确实有现实问题的人。传播只采用一对一私发，不公开投放。

每名用户原则上只提供 1 次完整体验；需要复测时由产品负责人单独放行。

通过条件：

- 至少 8 人独立完成 P1–P9。
- 没有未关闭的 P0 问题。
- 每次失败都能定位到技术、交互、问题质量或解读质量中的一种。
- 完成第一轮问题复盘，并只修复影响完成率或理解度的高频问题。

### Gate 4：最多 30 人受控公测

传播路径：同事或朋友的二度关系、私聊邀请、小范围共研群。此阶段仍不做公开主页挂链、广告投流、应用商店上架或收费。

用户进入前需看到简明说明：观象是基于易经卦象的 AI 辅助观察工具，不替用户决定人生；不要输入身份证、电话、真实姓名、公司机密等敏感资料。

反馈优先使用外部表单或人工编号台账，不为本轮专门开发复杂后台。联系方式与问题内容分开保存；案例公开必须另行取得明确授权。

通过条件：达到阶段最小证据量，且成本、风险和体验仍在控制范围内。

### Gate 5：阶段复盘与继续/调整/停止决策

复盘只回答四个问题：

1. 陌生用户能否独立完成？
2. 用户是否认为观象直接回答了问题，并能看懂判断依据？
3. 不同问题与不同卦象是否产生了可感知的差异，而非通用话术？
4. 用户是否出现再次使用、主动推荐或愿意接受延迟回访的真实信号？

Gate 5 后只能做三种决定：

- `CONTINUE`：核心价值信号成立，进入更大样本与解卦质量迭代。
- `ADJUST`：技术链路成立，但解读价值或表达方式不足，回到第十一模块的质量验证，不扩大推广。
- `STOP`：成本、安全或核心价值不成立，关闭公测入口并保留证据。

## 6. 最小数据与反馈设计

本阶段不建设大型数据系统，只记录决策所需的最小字段：

- 匿名案例编号；
- 是否独立完成 P1–P9；
- 卡住的页面和原因；
- 最终确认问题；
- 卦象与版本信息；
- 模型、提示词、知识和验证器版本；
- 输入/输出用量、生成耗时、失败与重试；
- 是否直接回答最关心的问题；
- 卦象依据是否清楚；
- 哪一段最有价值、哪一段像通用话术；
- 建议是否具体可执行；
- 是否有过度武断或不适内容；
- 是否愿意再次使用或推荐；
- 可选的延迟回访结果。

即时反馈不把“准不准”作为唯一指标。延迟回访重点询问现实变化、用户是否采取行动、哪些判断得到支持、哪些判断未成立，以及这次解读是否帮助其看清问题。

## 7. 阶段指标与决策线

最小证据量：

- 至少 20 个独立完成的有效体验；
- 至少 15 份结构化即时反馈；
- 至少 8 份自愿延迟回访；
- 覆盖多个问题类型，不能全部来自易经爱好者或熟人赞美样本。

继续扩大前至少满足：

- P1–P9 独立完成率不低于 80%；
- P0 安全、隐私、重复计费事故为 0；
- 模型成本未突破产品负责人设定的硬上限；
- 多数有效反馈认为回答切中最终问题且依据可理解；
- 出现可验证的再次使用或主动推荐信号；
- 案例评审能观察到由不同卦象带来的实质差异。

如果完成率达标但解读仍同质化，不扩大用户数，应回到解卦系统质量主线；如果解读评价较好但链路失败率高，优先修可靠性，不重写内核。

## 8. 单人推进方式

产品负责人只需要承担四类决定：

1. 确认每轮预算和停止线；
2. 提供或确认逐页手机截图中的具体问题；
3. 邀请测试者并收回反馈；
4. 在每个 Gate 做继续、调整或停止决定。

Codex 承担代码定位、分批修改、自动化测试、回归检查、缺陷整理和阶段证据汇总。每次只授权一个工作包，避免反复读取巨型前端文件和无关系统。

## 9. 推荐执行顺序

1. 先只处理匿名访问，不同时调整视觉。
2. 匿名链路打通后，用真实手机采集 P1–P9 截图和问题。
3. 按页面组完成移动端首轮修复。
4. 原 3 位同事复测。
5. 开放 10 人首轮测试并修复 P0/P1。
6. 开放最多 30 人受控公测。
7. 汇总即时反馈、延迟反馈、成本和故障，完成 Gate 5 决策。

## 10. 下一项可执行任务

下一项任务应单独立项为：

> 基于 V72 新建 V73 公测候选，只解除 Direct Reading V2 与 intake 的匿名访问阻塞，复用现有公开限流机制，补齐幂等与匿名链路测试；本任务不得修改 P1–P9 视觉、文案、辨识、排盘、解卦 Prompt 或 API 内容契约。

该任务验收通过后，再开始手机端逐页问题采集与修复。
