# 观象 V73 公测数据治理 v0.1

状态：`GATE_0_CANDIDATE`

对应工作包：`WP-G0-08`

## 1. 基本原则

- Product Beta 仅限成年人。
- 不主动收集真实姓名、身份证、出生资料、公司机密或第三方隐私。仅在用户单独同意
  回访时允许自愿填写一个联系字符串（邮箱、微信号或电话之一），不得与内容同库。
- 真实问题、模型原文、联系方式、原始凭证和未遮挡截图不得进入 Git、issue、
  fixture、提交信息或普通 QA 证据。
- 参与测试、同意回访、授权公开案例是三项独立决定。
- 以匿名案例 ID 关联研究记录；联系方式和案例内容物理分离。

## 2. 存储边界

### 运行时临时任务

- Python 内存中的 intake/reading 任务：统一披露并实现为最长 45 分钟。
- 现有隐私页“最长约 30 分钟”必须在 V73 修正为 45 分钟，或先修改实现后再采用
  30 分钟；不得继续出现文案与代码不一致。
- 临时任务到期自动清理；不进入 Git 或研究台账。

### 长期技术元数据

- 只保存请求摘要、凭证摘要、任务状态、次数、预留、实际成本和事故状态。
- 不保存问题原文、模型原文或原始凭证。
- 保留到 Gate 5 结束后 90 天，然后删除；无论 Gate 5 是否结束，绝对上限为收集后
  180 天。更长期保留需 PO 新决策和重新告知。
- 仅为限流可保存 keyed HMAC 的 IP 摘要；原始 IP 不落库、摘要不可导出到研究证据，
  最长 7 天且在最后相关窗口结束后尽快删除；HMAC 密钥与凭证/引擎密钥分离。

### 用户主动保存的观事簿

- V73 匿名公测入口禁用观事簿保存，不创建新的长期内容记录；V72 既有入口和数据行为
  不删除、不迁移、不修改。
- 若未来为V73启用，必须先升级数据规范，冻结存储、备份、导出、删除和绝对保留期，
  并由PO、QA和反向论证重新批准；不得把V72既有能力直接当作公测授权。

### 公测研究证据

- 仓库外证据根由运行前设置 `GX_EVIDENCE_ROOT`，必须位于本 Git 工作区之外并由
  操作系统访问控制保护。
- 启动时必须把 Git 根和证据根解析为规范化绝对路径，拒绝证据根等于/位于 Git 根
  内、符号链接或 Windows 重解析点回穿 Git 根；不满足即 fail closed。
- 内容库：匿名案例 ID、脱敏问题、输出、即时反馈和回访。
- 联系库：匿名案例 ID、邀请渠道、回访联系方式和单独同意状态。
- 两库不得保存在同一文件或同一表中。
- Git 只保存 `manifest.json` 的脱敏摘要与 SHA-256，不保存原始证据。

## 3. 保留和删除

- 联系方式：回访完成后 7 天内删除，且最迟不超过收集后 45 天。
- 未获案例授权的问题、输出和反馈：Gate 5 结束后 30 天内删除，绝对上限为收集后
  90 天。
- 成本与无内容审计元数据：Gate 5 结束后 90 天删除。
- 用户删除或撤回请求：7 天内完成，并覆盖活动副本、导出和外部表单副本。
- 获得案例授权也不授权公开联系方式、出生资料或可识别第三方信息。

删除责任人：PO 或 PO 明确指定的一名数据保管人。执行代理和审查代理不得访问原文。

匿名参与者持有一次性删除密钥（不少于 128 bit，只存摘要）作为删除授权；若密钥
遗失，只能通过已登记的回访联系方式验证。仅凭案例 ID 不得删除或导出任何数据。

## 4. 收集字段

允许：匿名案例 ID、版本、设备类别、页面进度、完成状态、故障分类、用量和成本、
结构化评分、用户自愿提供的反馈、回访同意。

禁止：出生日期/时间/地点、身份证、金融账户、医疗记录、真实第三方身份、密钥、
验证码、完整请求头、原始体验凭证。

用户误填禁止字段时：停止把该记录用于研究，登记 S0/S1 数据事件，按删除流程处理，
只保留不含原文的事件摘要。

Gate 1 必须在“问题/澄清/最终问题”字段使用合成身份证、出生日期/时辰/地点、电话
和银行卡样例验证：这些内容不得进入 Provider、Git 或普通 QA 证据，Provider 调用
和预算预留为 0。单独同意的联系字段可保存一个联系字符串，但永不发送给 Provider。

## 5. 访问与证据

- 原始数据访问：PO 和一名经登记的数据保管人。
- PMO：只访问数量、状态和脱敏摘要。
- QA/反向论证/执行代理：只访问合成用例、遮挡截图和哈希清单。
- 外部表单在提供方、权限、导出和删除能力未确认前不得启用。
- Provider 请求必须冻结 `store=false`（或官方等价的不持久化配置）并纳入隐私披露；
  若模型提供方的数据处理/保留事实无法确认，真实调用保持关闭。
- 当前项目数据控制状态登记为 `UNKNOWN_DEFAULT_ASSUMED`。`store=false` 只控制应用
  状态，不代表零保留；按 OpenAI 官方数据控制说明，默认滥用监控日志可能包含提示、
  响应和派生元数据，并最多保留30天，法律或安全原因可能更久。只有经OpenAI批准的
  ZDR/MAM 才能改变该边界：
  `https://developers.openai.com/api/docs/guides/your-data#default-usage-policies-by-endpoint`。
- 首次真实调用前，PO/运维操作人必须在仓库外保存项目实际为DEFAULT/MAM/ZDR的
  控制台证据并更新manifest。未取得ZDR/MAM证明时一律按DEFAULT向参与者披露；本地
  删除只能删除本项目副本，不能承诺删除Provider依法或按政策保留的日志。
- 每次证据导出必须运行脱敏检查并生成 SHA-256 manifest。

## 6. 事件处置

私下误填禁止字段且被入口阻断、及时删除、未进入 Provider/Git 的事件为 S1；进入
Git/Provider、跨用户读取或公开泄露为 S0。S0 立即执行隐私紧急停止，POST、GET、
intake 全部关闭，直至完成影响评估和删除验证。
