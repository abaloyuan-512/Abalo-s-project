# 观象 Sites 体验规范 V5

状态：P1–P9 发布候选基线
确认日期：2026-08-16
替代范围：本规范继承 V4；仅版本化 P9 动态载荷与正式接线。确定性排盘规则没有变化。

## 1. 用户动线

- 原题无歧义：P1 → P2 → P3 → P6 → P7 → P8 → P9。
- 原题触发既有辨识器：P1 → P2 → P3 → P4 一次澄清 → P5 确认 → P6 → P7 → P8 → P9。
- P1、P2、P3、P4/P5、P6、P7、P8 的冻结边界继续以 V4 为准。

## 2. P9 动态载荷

- P9 使用 `GUANXIANG_P9_FINALE_V1`。
- P9 与九章正文来自同一次 fixed-high 模型调用；额外模型调用数必须为零。
- 模型完整输出先生成九章正文，随后追加唯一标题 `## 观象寄语` 和恰好两行正文。
- 第一行直接回答原问题；第二行只写最关键的行动边界。
- 两行不得包含经典原句、日期、必然保证、第三方读心、HTML、Markdown 标记或系统信息。
- 后端必须先拆出 P9，再对九章正文按原规则核验和机械映射；因此 P8 的正文切片、SHA 与排盘来源不受 P9 影响。
- P9 缺失、格式错误或未通过内容核验时整次结果阻断；不得使用样例、模板或旧五板块回退。

## 3. 客户呈现

- P7 只显示卦象、卦名、卦序和详细读卦入口，不显示所问问题。
- P8 继续呈现冻结五幕。
- P9 只呈现定稿“观象寄语”页面：卦象标签、两句动态答案、继续追问、分享解卦和本地观事簿入口。
- 旧“判断、适合做、不适合做、反向风险、转向条件”保留为内部完整正文的可追溯映射，不在客户 P9 展示。
- 经典原句尾注方案已取消，不得恢复。

## 4. 发布门

1. clear 与 ASK_ONCE 两条真实动线均可抵达同一个 P6–P9 链路。
2. 每次请求只有一次确定性排盘、一次 fixed-high 调用、零自动重试和零 P9 追加调用。
3. Python 全量 `pytest`、Sites 全量 test/build/lint 通过。
4. 正向、反向、失败恢复与回归验收通过。
5. Render 必须发布统一发布候选的 monorepo SHA；Sites 可以发布从该 SHA 精确导出的 `sites/hosted-app` source commit。发布记录必须同时保存两者及相同的站点源树 SHA；任一端未更新都不得宣称上线。
6. 线上最终验收必须确认真实 P9 两句话不是离线样例，且旧五板块没有出现在客户页面。
