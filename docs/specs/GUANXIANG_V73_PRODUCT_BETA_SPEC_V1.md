# 观象 V73 Product Beta 1 规范 V1

状态：`GATE_0_CANDIDATE`

上游基线：`MEIHUA_SITES_EXPERIENCE_SPEC_V6`、V72 冻结标签
`guanxiang-p1-p9-v72-frozen-20260817`

## 1. 目标

V73 只把 V72 推进到“匿名、限次、可停止、可核验的手机端受控公测”。它不重做
产品内容、辨识、排盘或解卦契约，不改变 Meihua 引擎 Phase 1 / Phase 2 定义。

## 2. 唯一主线

```text
CLEAR：P1 → P2 → P3 → P6 → P7 → P8 → P9
ASK_ONCE：P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8 → P9
```

匿名参与者不注册账号、不登录 ChatGPT，使用一个限次、可撤销、可过期的体验凭证。
同一凭证只允许启动一次完整体验；同一任务的轮询和恢复不重复消耗次数。

## 3. Gate 1 允许的产品变化

- 为 Direct Reading V2 POST、GET 与 intake 增加统一体验凭证校验。
- 将凭证摘要与 intake/reading 任务不可逆绑定。
- 增加调用前的全局预算、次数、频率、并发、幂等和停止开关。
- 增加高风险输入安全退路；安全退路不排盘、不调用 high、不输出卦象结论。
- 修复公开响应、错误提示和隐私说明中与上述控制直接相关的内容。
- 补齐数据库迁移、合成测试、fixture、测试脚本和操作文档。

Gate 1 不修改 P1–P9 视觉和移动排版。Gate 2 才允许移动端响应式修复。

## 4. Gate 2 允许的产品变化

- 仅调整响应式布局、字号、行宽、间距、溢出、视口高度、安全区、触控面积、
  键盘遮挡、滚动/返回/弱网恢复与无悬停降级。
- 不改变冻结文案、页面顺序、唯一动线、图片美术方向、内容契约或模型 Prompt。

- `sites/hosted-app/drizzle/**` 中对应版本化迁移
- `sites/hosted-app/app/privacy/page.tsx`

  入口的统一安全退路、禁用V73匿名观事簿、错误恢复及 Gate 2 移动适配部分
- `sites/hosted-app/app/globals.css` 中 Gate 2 移动规则
- `sites/hosted-app/tests/**`、`sites/hosted-app/package.json`
- `tests/**` 中新增或更新的合成安全与回归测试

任何超出清单的文件，执行代理必须先回到 PMO 申请扩围并取得 PO 批准。

`tests/**` 只允许增加测试或为已批准契约作等价更新；不得删除、跳过、放宽断言、
降低基线数量或改写金标来使实现过门。新模块必须使用明确的数据模型和类型标注，
缺少任一项即 QA `FAIL`。

## 6. 明确禁止修改

- `streamlit_app.py`
- `iching_tools.py`
- Direct Reading high 的模型、Prompt、输出章节、P8/P9 内容契约和验证边界
- P1–P9 冻结文案、视觉母题、页面顺序和唯一动线
- V72 标签、V72 站点版本、V72 构建摘要和冻结记录
- 任何真实用户问题、模型原文、联系方式、原始凭证或出生资料进入 Git

## 7. 匿名凭证与任务

- 一人一凭证，一次完整体验；有效期候选为签发后 7 天；凭证使用密码学安全随机数，
  熵不少于 128 bit。
- 仅打开邀请页或微信链接预览不消耗次数。
- POST、GET、intake 均校验同一凭证；A 凭证不得读取 B 任务。
- 凭证只保存不可逆摘要，原文不得进入日志、响应或数据库。
- 跨设备默认不支持；补发前撤销旧凭证并记录原因。
- 凭证使用者无法与邀请记录合理对应时，不计入“不同用户”产品证据。
- 安全退路会消耗并终结本次凭证，状态记为 `SAFETY_EXITED`，但不产生模型次数或
  预算预留；重新体验只能经人工复核后撤销旧凭证并补发。

## 8. 高风险输入候选边界

Product Beta 仅限成年人。以下问题不得进入正常排盘与解卦：

- 紧急医疗、诊断、用药剂量、生死；
- 自伤、他伤、家庭暴力或迫近人身危险；
- 违法实施、武器、诈骗或规避执法；
- 赌博、证券/加密资产具体交易；
- 借贷、破产、重大法律时限或诉讼策略；
- 任何混合问题中包含上述迫近危险或重大不可逆专业决定的部分。

无法可靠判断时默认进入安全退路。安全退路只说明边界和现实求助方向，不提供
卦象结论、具体操作、日期或结果保证。任一固定高风险用例产生越界指令为 S0。

同一安全边界必须在原始问题、P4 澄清答案和最终重述问题三个自由文本入口执行；
任一入口变为高风险都终止正常流程。安全判断不得新增未纳入预算和数据披露的模型
或第三方分类调用；V1 使用本地版本化规则并以正例、隐晦例和邻近反例共同验收。

## 9. 数据与证据

- 真实问题、模型原文、联系方式和截图原件存放在仓库外的受限证据目录。
- Git 只保存合成用例、脱敏摘要和证据清单的 SHA-256。
- 参与测试不等于授权公开案例；回访和案例传播分别取得同意。
- 不收集出生资料。若用户误填，停止处理并按数据政策删除。

## 10. 发布与停止

- 付费生成默认关闭；缺配置、控制库失败或预算状态不确定时 fail closed。
- V73 使用新分支、新规范、新提交、新标签和新站点版本，不覆盖 V72。
- Gate 1 通过前不得匿名开放；Gate 2 通过前不得进入真实用户测试。
- 任一 S0、预算穿透、跨用户读取、敏感信息泄露或重复付费调用立即停止。
- 恢复必须有 QA PASS、反向论证无阻断和 PO 明确 GO。
