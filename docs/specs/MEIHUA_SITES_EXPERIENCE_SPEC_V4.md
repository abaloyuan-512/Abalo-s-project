# 观象 Sites 体验规范 V4

状态：产品基线已确认
确认日期：2026-08-15
替代范围：本规范与旧体验规范、旧治理记录或历史页面接线冲突时，以本规范为准。

## 1. 冻结范围

- P1 首页：保持定稿，不修改。
- P2 观象之法与准备：保持定稿，不修改。
- P3 正问：保持定稿；提交后由系统自动判断是否需要辨识。
- P4/P5：沿用已经完成的 `SITES_CONDITIONAL_INTAKE_PRODUCT_V1`，不修改其模型、提示词、一次性判断规则、失败处理或跳过规则。
- P6：三个数字只交给确定性程序排盘；AI 不参与排盘。
- P7：只呈现卦象、卦名、卦序等既定内容和“查看详细解卦”入口，不显示所问问题。
- P8：保持已定稿的五幕视觉和交互；只做数据接线。
- P9：保持已定稿的“观象寄语”文本结构、内核、视觉和交互，不再呈现旧版五个信息板块。

## 2. 页面动线

### 原题足够明确

P1 → P2 → P3 → 自动判断 `PASS` → P6 → P7 → P8 → P9。

`PASS` 不展示 P4，也不进入 P5。

### 原题存在关键歧义

P1 → P2 → P3 → 自动判断 `ASK_ONCE` → P4 只问一个既定澄清问题 → P5 确认最终问题 → P6 → P7 → P8 → P9。

本版本不把一次澄清升级为多轮，也不重新设计辨识器。

### 辨识服务异常

保持现有触发系统的 `FAIL_OPEN` 规则：原题不改写，按 `CLEAR` 路径继续；不得伪造已经完成的辨识结果。

## 3. 数据与内容边界

- 原始问题必须原样保留；澄清回答作为附加上下文，不得冒充已验证事实。
- 条件辨识不接触三个数字，不触发排盘，不触发 Direct Reading。
- P6 之后只允许一次确定性排盘和同一请求编号下的一次 Direct Reading high 任务。
- P8 可机械映射同一次排盘事实和已通过核验的正文，不得新增模型调用。
- P9 只能消费已经通过其冻结系统生成并审核的终章载荷；不得从旧五板块、九章正文或通用模板临时压缩、补写两句答案。
- P9 终章载荷缺失时必须明确阻断，不能回退展示旧版“判断、适合做、不适合做、反向风险、转向条件”。

## 4. 验收门

1. `PASS` 路径从 P3 直接进入 P6。
2. `ASK_ONCE` 路径只问一次，并经过 P5 显示和确认最终问题。
3. P6 的三数由确定性程序排盘，且失败时保留输入与请求编号。
4. P7 不显示所问问题，详细解卦入口进入冻结 P8。
5. P8 五幕保持冻结视觉，不显示旧版 P9 五板块。
6. P9 与已验收的桌面、移动端终章一致。
7. Python 全量测试、前端 build/test/lint 和两条浏览器旅程全部通过。
8. 发布清单记录源码 SHA、规则版本、提示词版本、部署地址和验收人；本规范本身不构成部署授权。
