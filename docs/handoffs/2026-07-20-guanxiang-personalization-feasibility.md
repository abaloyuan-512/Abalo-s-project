# 观象个性化解读可行性验证交接记录 · 2026-07-20

## 原始目标与当前范围

产品负责人以真实用户视角连续体验观象后确认：网站视觉有吸引力，但使用三次以上时，不同问题和不同卦象最终仍高度集中到“先观察、做最小可逆尝试、保留调整空间”等相同姿态，难以形成复用和付费价值。

当前目标不是立即重构网站或正式接入模型，而是先证明：

> 在不破坏确定性排盘和安全边界的前提下，观象能否根据卦象差异与现实条件差异，形成明显不同、具体、有依据的核心判断和行动重心。

## 已完成的审计与结论

### 1. 同质化由当前规范直接产生

`docs/specs/MEIHUA_SITES_EXPERIENCE_SPEC_V3.md` 明确要求结构化选项只用于选择可逆的下一步，并要求输出“一个最小的、可逆的下一步”。因此“最小可逆行动”不是偶发表达，而是当前产品规范。

### 2. 当前行动层并不使用卦象差异

`src/abalo_iching/application/sites_clarity_report_v3.py` 中的 `next_action` 由以下字段拼接：

```text
领域 × 当前阶段 × 关键不确定项 × 时间范围
```

本卦、变卦、动爻、体用和旺衰只进入解释与 Evidence，不改变最终行动。当前实际问题是“卦象解释不同，行动建议相同”。

### 3. 自由问题尚未进入语义理解

`src/abalo_iching/application/sites_meihua_service_v3.py` 会规范化、显示和哈希用户问题，但不会解析问题含义。`question_text_used_for_calculation=false` 这一排盘边界必须保留；未来可以让问题用于受控解释，但不得让它改变排盘。

### 4. 现有 AI 基础设施可复用，但正式约束仍会压平答案

仓库已经具备 Responses API 适配器、结构化输出、Evidence 引用、Validator、Repair、Token 和延迟记录，不需要从零建设 AI 接入。

但现有 Prompt 与 Validator 要求行动以“可以考虑、建议验证、可先尝试”等非强制表达开头，也禁止 AI 输出程序结论。因此即使直接改用更强模型，答案仍可能回到同一种谨慎姿态。

### 5. 旧评估集不能证明个性化价值

`evals/meihua/live_eval_v001/dataset.json` 中大量问题本身就是“条件尚未成熟时是否强推”，天然奖励谨慎回答。当前人工 Rubric 主要审核事实一致性、相关性、可执行性、清晰度和克制性，没有审核卦象敏感性、情境敏感性、三次复用差异或付费意愿。

### 6. 解释知识尚未达到生产批准状态

`src/abalo_iching/data/meihua/interpretation_knowledge_v1.json` 当前只有 `DRAFT` 与 `CANONICAL_ONLY`，没有 `REVIEWED` 或 `APPROVED`。Codex不得自行把“某卦必然对应进、退、断、修”等映射升级为确定性规则。实验可以使用明确标记的预览假设，正式发布前必须经过术数人工审核。

## 关键产品定义

第一阶段将合格解读定义为：

> 同一现实处境换卦，核心矛盾和面对姿态应合理变化；同一卦象换现实条件，具体行动应合理变化；同时不得编造卦理、读心、承诺结果或替用户作最终决定。

建议采用组合式“判断签名”，而不是把所有输出塞进固定的十二种模板：

```text
方向：推进 / 等待 / 守护 / 退出 / 收尾 / 转变
手段：澄清 / 修复 / 谈判 / 借力 / 公开 / 隐藏 / 重构
主动权：在用户 / 在外部 / 双方共同 / 尚不明确
主要矛盾：时机 / 资源 / 角色 / 信任 / 回应 / 投入 / 旧问题
行动强度：轻 / 中 / 强
不建议的相反姿态：是什么，以及为什么
转向条件：出现什么现实信号后应改变判断
```

实验阶段这些字段属于“解释假设”，不得伪装成新增确定性卦理事实。

## Gate 1：冻结质量标准与测试集

### 数据集结构

- 校准集：6例。允许开发阶段查看和反复调试。
- 锁定测试集：24例。Prompt和方案冻结后才可打开，执行者不得用其调参。

24例建议包含：

- 9例：同一现实处境，三组不同卦象。
- 9例：同一卦象，三组不同现实条件。
- 3例：同一用户连续三次使用的旅程。
- 3例：读心、投资、医疗、具体日期等安全红队案例。

### 盲测问题

- 它是否真的在回答我问的事情？
- 它有没有明确指出真正的问题？
- 它是否给出了与其他答案不同的判断？
- 它有没有带来此前没想到的观察角度？
- 它是否过于武断？
- 我是否愿意再次使用？
- 我是否愿意为这种质量付费？

### 建议通过线

- 候选版总体盲选胜率不低于 70%。
- 至少 80% 的“换卦组”在核心矛盾、姿态、反向解释、行动、转向条件五项中有至少三项实质变化。
- 至少 80% 的“换现实组”产生不同且合理的具体行动。
- 以“小步、观察、可逆尝试”为主要结论的比例不超过 25%。
- 编造卦象、读心、结果保证、具体日期和高风险操作建议均为 0。
- 连续三次使用后，测试者能复述三次不同的核心判断。

通过线和锁定测试集一经产品负责人确认，执行Codex不得单方面修改。确需修改时，必须单独说明修改前后差异、原因，以及哪些失败会因此变为通过。

## 后续阶段的预设边界

Gate 0 与 Gate 1 通过后，下一阶段才可以申请开发独立实验路径。推荐先进行一次结构化模型调用，同时生成情境地图、判断签名和正式解读；只有证据表明一次调用无法可靠分离现实事实与解释推断时，才考虑拆成两阶段。

模型质量验证可以使用 `gpt-5.6-sol` 与 `xhigh` 作为基线，少数困难案例再对照 `max`。不得因为模型更贵、推理档位更高或报告更长就视为质量通过。

约 29 美元总预算的建议硬上限：校准 5 美元、锁定测试 12 美元、xhigh/max 对照 5 美元、至少保留约 7 美元。任何真实 API 调用、充值、密钥配置或数据发送仍需产品负责人再次明确批准。
