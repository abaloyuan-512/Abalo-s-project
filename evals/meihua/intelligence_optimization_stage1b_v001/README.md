# 观象智能能力优化阶段1B

状态：`AUTHORIZED_SCOPE_FREEZE`

## 唯一验证命题

在提出 `decision_bottleneck_hypothesis` 前，先识别决策轴、用户前提、行动主体/授权、动机/担忧，并只追问当前最能改变问题定义的一个缺口，是否能明显改善关键痛点辨识与卜题建议？

## 允许范围

- 使用阶段1的 M01—M04 冻结输入；
- 新增并冻结 M05—M06 两个保护案例；
- 在本评估目录实现隔离合同、Prompt、runner、验证器与测试；
- 记录调用、token、延迟、失败、决策、风险和偏差；
- 由产品负责人进行一次最低负担价值评价。

## 禁止范围

- 不修改或接入生产辨识 V1；
- 不修改 UI、API、route、数据库或用户流程；
- 不排盘、不起卦、不解卦、不建设案例库；
- 不执行阶段2；
- 不把合成回答写成真实用户认可；
- 不根据 M05—M06 的逐案答案编写 case-specific Prompt。

## 最小流程

1. `FRAME_CHECK`：输出决策框架与最高价值缺口。
2. 若缺口会改变问题定义：`ASK_CRITICAL`，全流程最多新增一个问题，不得提出瓶颈或卜题。
3. 若框架足够：`CONFIRM`，向用户确认瓶颈理解并允许纠正。
4. 只有确认/纠正后：`COMPLETE`，输出 1—2 个不同焦点的卜题候选。

唯一追问后仍不足时必须停止为 `INSUFFICIENT_TO_HYPOTHESIZE`；不得再问第二个问题，也不得强制完成。
