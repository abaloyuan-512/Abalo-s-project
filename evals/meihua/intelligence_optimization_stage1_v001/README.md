# 观象智能能力优化：阶段 1 辨识最小实验 v1

## 当前状态

`AUTHORIZED_IN_PROGRESS`

## 唯一目标

验证在现有辨识流程之外增加以下最小推理顺序后，是否能让用户明显感到“找到了真正卡点”，而不只是更完整地总结信息：

1. 形成可被否认的 `decision_bottleneck_hypothesis`；
2. 关键依据逐句追溯到用户原话；
3. 在完成前明确让用户确认或纠正该理解；
4. 最多提供两个卦题候选，并说明各自检验的决策矛盾。

## 范围锁

允许：

- 新建隔离的实验合同、验证器、测试和运行记录；
- 使用阶段 0 冻结的 4 个合成辨识案例；
- 为合成案例增加明确标记的确认/纠正脚本；
- 记录模型调用次数、token、延迟和失败；
- 生成旧版 A / 实验版 B 的对照材料；
- 由产品负责人只做一次、四案例的最小价值判断。

禁止：

- 修改或接入生产 `SITES_GUIDED_INTAKE_CONTRACT_V1`；
- 修改解卦、排盘、UI、API、数据库或旧入口；
- 建设案例库、检索系统或阶段 2 的同现实换卦实验；
- 让 Codex、模型或 PMO 冒充真实用户完成主观价值验收；
- 未经用户确认自动进入阶段 2。

## 验收标准

阶段 1 不是以代码存在为完成，而是同时满足：

1. 实验合同强制区分 `ASK / CONFIRM / COMPLETE`；
2. 未经过用户确认或纠正，不得完成并输出候选卦题；
3. 瓶颈证据与候选题依据必须能追溯到用户原话；
4. 候选卦题最多两个，且不能只是同义改写；
5. 4 个冻结案例均生成可比较的新旧对照，技术验证无越界；
6. 产品负责人按 V2 锚点完成一次最小对照评价；
7. 新版在“辨识超越总结”上形成明确增量，并且不破坏 GXID-M04 的自然承接保护模式；
8. PMO 通过范围、风险和验收复核；
9. 用户确认后才可进入下一阶段。
