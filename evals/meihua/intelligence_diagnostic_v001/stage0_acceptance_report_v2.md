# 《观象智能能力优化终版方案》阶段 0 验收报告 v2

## 验收结论

阶段状态：`PASS_WITH_OPEN_ITEMS`

阶段 0 预设的两个核心问题已经获得足以支持内部产品决策的证据结论：

1. 当前辨识**不能稳定超越信息总结并形成经用户确认的决策瓶颈洞察**。
2. 当前解卦**不能稳定证明核心判断是因为该卦而成立**，并存在把现实信息混入卦象证据的明确边界问题。

本结论允许向用户**建议**进入阶段 1 最小实验，但不自动授权进入。未经用户确认，不修改产品代码、Prompt、模型、UI、知识库或排盘规则。

## 本轮证据构成

- 10 个诊断案例：4 失败、4 中间候选、2 保护。
- 4 个冻结当前版本的完整合成辨识过程。
- 4 个可复现的历史模型解卦与确定性盘面映射。
- 1 名产品负责人完成的三角色内部盲评；原件与标准化结果在揭盲前冻结。
- 用户自由评论形成的逐案例质性证据表。
- 按明确规则重做的 10 例产品边界客观核验。
- 用户价值、易学结构、产品边界三份行为锚点 V2。

不把合成案例写成真实用户案例，不把产品负责人写成独立普通用户或易学专家，不把旧分类评分计算成均分或通过率。

## 核心问题一：辨识是否超越总结

结论：`PROBLEM_EFFECTIVELY_VALIDATED_INTERNAL_HIGH_CONFIDENCE`

### 支持证据

四个具备完整辨识材料的当前模型样本中：

- GXID-M01：产品负责人判断为 `NO`。连续承接中加入未经用户确认的前提，最终让用户感到问题被替换；冻结流程在四次回答后仍未完成。
- GXID-M02：判断为 `PARTLY`。有效地把投入条件具体化，但最终题目主要重组用户已经提供的退款率、维护成本和履约条件，没有形成明显的新决策结构。
- GXID-M03：判断为 `PARTLY`。过早进入资源、责任和时间核实；没有先理解为什么想推动、真正顾虑什么。
- GXID-M04：判断为 `CLEARLY_YES`。问题逐轮承接上一句回答，没有额外假设，是必须保护的正向模式。

这些类别只表达方向，不计算 1/4 或 3/4 通过率。真正重要的是跨案例模式：当前流程有能力做到自然承接，但缺少强制验证“决策瓶颈是否已识别、是否来自用户、用户是否认可”的完成条件，因此表现不稳定。

### 已定位原因

1. 当前完成条件更接近“事实和未知是否收集够”，而非“为什么无法决定是否已经被识别”。
2. 模型归纳可以在未获用户确认时进入下一轮问题，造成假设升级和谈话带偏。
3. 最终问题常把用户已说的条件重新排列，提升了具体性，却没有产生新的矛盾结构。
4. 辨识得到的信息没有稳定进入后续解卦；GXID-M04 的辨识获认可，但解卦仍被认为没有使用用户已经回答的大量信息。

### 阶段 1 应验证的最小假设

不重写整体流程，只验证加入以下内部思考顺序后，辨识能否明显超越总结：

1. 形成 `decision_bottleneck_hypothesis`，说明用户为什么现在无法决定；
2. 每个关键前提逐句追溯到用户原话；
3. 允许用户明确回答“这个理解不对”；
4. 最多提供两个卦题候选，并说明二者分别检验什么决策矛盾；
5. 完成条件从“信息够了”改为“瓶颈假设已被用户确认或修正”。

## 核心问题二：解卦是否因卦而改变判断

结论：`CAUSAL_LEGIBILITY_PROBLEM_VALIDATED_INTERNAL_HIGH_CONFIDENCE; COUNTERFACTUAL_EFFECT_UNMEASURED`

### 支持证据

1. 4 个 Gate 0 失败组已经证明：同盘、同结构化输入下只换自由问题，报告逐字段相同。现实决策差异没有进入判断层。
2. 四个具备完整盘面映射的当前模型样本，产品负责人的卦象增量判断分别为 `NO`、`PARTLY`、`PARTLY`、`NO`，没有一个让评审者看见“核心判断必须由该卦推出”的完整因果链。
3. 技术 evidence id 存在，但用户仍明确感到“换成别的卦也成立”“主要是管理学建议”。这说明引用存在不等于因果成立。
4. 客观边界审计发现：4 例补写现实事实、1 例第三方读心、6 例把现实输入放入仅标为卦象证据的判断；7 例至少存在一个已确认硬失败。
5. 两个保护样本继续证明“先回答—具体卦理—现实行动”的结构和口语感有价值，但它们也包含现实历史补写或读心，因而只能保护表达结构，不能原文冻结。

### 已定位原因

1. 系统能证明“引用过卦象证据”，不能证明“核心结论必须由这个卦推出”。
2. 现实背景、通用建议和卦象判断在同一句中混合，证据标签把整句归为 `CHART_EVIDENCE`。
3. 输出常跳过盘面事实到现实判断之间的解释桥梁，直接进入边界、机制、阶段复盘等通用建议。
4. 保护样本显示用户需要明确判断，但明确判断不能以补写事实、读心或保证结果为代价。

### 尚未执行的验证

“同现实换卦”反事实实验属于终版方案阶段 2，本阶段没有提前执行。因此当前高置信确认的是“卦象因果链不可见、引用不等于因果、现实信息被混入卦证”的问题，不能进一步声称实际换卦不会改变判断，也不能声称已经测得不同卦象的因果效应大小。

## 产品边界复核结果

旧工作簿中的产品边界勾选退出验收：9/10 把“生成未提供日期”误判为硬失败，说明字段定义不足。

V2 规则审计结果：

- 生成未提供日期：0/10；所有可见时间范围均来自用户材料。
- 替用户决定或保证结果：0/10；明确给出有条件倾向不等于替用户决定。
- 捏造现实事实：4/10。
- 第三方读心：1/10。
- 现实冒充卦象证据：6/10。
- 高风险医疗、财务、法律指令：0/10。
- 至少一个已确认硬失败：7/10。
- 无已确认硬失败但材料仍不完整：3/10。
- 正式全面通过：0/10。

所有 11 个硬失败命中均记录了逐字原文、盲包字段路径和规则理由。未审核知识状态与敏感数据留存需要引用链、日志和存储证据，当前保持 `CANNOT_CHECK`。

## 评分工具纠偏结论

1. 不要求用户重填旧工作簿。
2. 用户价值只保留两个核心问题，并提供 `CLEARLY_YES / PARTLY / NO / CANNOT_JUDGE` 的行为锚点。
3. `CANNOT_JUDGE` 和 `UNCERTAIN` 是材料边界，不是中间分。
4. 产品硬门由规则和逐字证据检查，不再让用户重复勾选。
5. 易学六项使用正向、可核对的定义，但在没有独立易学评审前不得宣布易理通过。
6. 用户只承担不可替代的体验判断：是否被理解、是否找到关键痛点、是否愿意采用卦题、是否感到判断必须因该卦而成立。

## 开放项与进入下一阶段建议

开放项：

- 没有真实目标用户完整案例；
- 没有独立易学专家结论；
- 知识审核状态和敏感数据留存尚未完成系统级检查；
- 同现实换卦实验尚未执行。

这些限制阻止我们宣称产品价值、易理正确性或安全边界已经全面通过，但不再阻止针对已证实的辨识问题开展阶段 1 最小实验。

建议：`ENTER_STAGE1_AFTER_USER_CONFIRMATION`。

阶段 1 只验证“瓶颈假设 + 用户确认 + 最多两个卦题候选”能否让辨识明显超越总结；不得同时改解卦、建设案例库或重构整体架构。
