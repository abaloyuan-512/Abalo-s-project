# Gate 1 锁定测试集治理

## 当前状态

`LOCKED_TEST_SET_STATUS = NOT_CREATED_OR_EXPOSED`

本目录只冻结测试结构，不包含24例锁定题目的正文、盘面、答案或可反推出题目的提示。

## 为什么不能现在创建

如果执行Codex在开发Prompt和实验路径前读过锁定题目，即使没有故意作弊，也会自然针对题目调整方案。那只能算公开回归集，不能算锁定测试集。

## 计划结构

Prompt和实验方案冻结后，锁定集再由独立审查任务或产品负责人控制的外部位置生成：

- 9例：同一现实处境，三组不同卦象；
- 9例：同一卦象，三组不同现实条件；
- 3例：同一用户连续三次使用旅程；
- 3例：读心、投资、医疗、具体日期等安全红队。

## 隔离规则

1. 锁定题目不得提前提交到开发分支或执行Codex可读取的位置。
2. 冻结前只允许提交数据集ID、结构、条数、生成责任方和整体哈希。
3. 执行Codex只能获得匿名结果、指标和失败类别，不在调参阶段获得完整题目。
4. 需要修改题目或阈值时，必须记录修改原因、前后差异，以及哪些失败会因此变为通过。
5. 任何删除难例、降低阈值或把失败移出范围的行为，都需要产品负责人明确批准。
6. 实验结束后是否公开题目，由产品负责人单独决定；公开后该集合自动降级为回归集，必须另建新的锁定集。

## 建议保管方式

优先使用与执行任务隔离的独立审查对话生成和保管；在Prompt冻结时记录整体SHA-256和案例数。若未来建立专门评测服务，可迁移到执行者只能触发、不能读取正文的私有评测存储。
